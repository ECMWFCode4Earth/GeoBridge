# GeoBridge Discovery Module — Reference Notes

Source: `geobridge/modules/discover.py`. Last reviewed against commit `c0640a6`.

## 1. What it does

`discover()` / `discover_one()` answer "what Copernicus datasets exist and
how can I access them?" — entirely **offline**. No network call is made and
no authentication is required (contrast with `extract` and `cds_download`,
which need `gb.authenticate()`).

Instead of querying ECMWF's live STAC catalogue at call time, GeoBridge
reads three **bundled YAML snapshots** that ship inside the package:

| File | Role |
|---|---|
| `geobridge/semantic/arco_snapshot.yaml` | Primary source. All ARCO-available datasets: Zarr URLs, subsets, variables, dimensions, WMTS endpoints. Generated by `scripts/refresh_arco_catalogue.py`. |
| `geobridge/semantic/cds_snapshot.yaml` | Auxiliary STAC metadata (title, abstract, keywords, licence, CDS retrieve/form/constraints links) for datasets not necessarily in ARCO. Generated by `scripts/refresh_catalogue.py`. |
| `geobridge/semantic/arco_overrides.yaml` | Small hand-maintained file: CDS-long-form ↔ ARCO-short-form variable name aliases (e.g. `2m_temperature` ↔ `t2m`). |

**Why a snapshot instead of live queries:** keeps GeoBridge offline-by-default
and makes the catalogue a versioned, reproducible part of the library rather
than a runtime dependency on ECMWF's STAC service. Users never refresh the
snapshot themselves — they get whatever was bundled with the installed
GeoBridge version. All three files are cached in-process via `@lru_cache`
after first load.

## 2. Dataset ID conventions

Two naming conventions coexist and `discover.py` bridges them automatically:

- **ARCO style**: underscores — `reanalysis_era5_single_levels`
- **CDS style**: hyphens — `reanalysis-era5-single-levels`

`discover()` builds its internal id set preferring the ARCO (underscore)
form when a dataset exists in both catalogues, and falls back to the CDS
(hyphen) form for CDS-only entries. `discover_one()` accepts either form
transparently.

## 3. `LayerDescriptor` — the unified return type

Every result is a `LayerDescriptor` dataclass combining STAC metadata with
GeoBridge's own access-method bookkeeping:

**Metadata**: `id`, `title`, `service` (`C3S`/`CAMS`/`CEMS`), `abstract`,
`variables`, `keywords`, `license`, `providers`, `thumbnail`.

**Extent**: `bbox` (west, south, east, north in WGS-84), `crs`
(`EPSG:4326`), `time_range` (start/end `datetime`), `time_step`.

**Access method fields** (`None`/empty = not available for this dataset):

| Field | Meaning |
|---|---|
| `zarr_time_chunked`, `zarr_geo_chunked` | ARCO Zarr URLs (see [EXTRACT.md](EXTRACT.md) for the two chunking flavours) |
| `wmts_url`, `wmts_layer_name`, `tile_matrix_sets` | WMTS preview endpoint (see [WMTS.md](WMTS.md)) |
| `cds_retrieve_url`, `cds_form_url`, `cds_constraints_url` | CDS "retrieve" job API links |
| `cds_download_supported` | `True` only once a dataset has been manually verified to round-trip correctly through `gb.cds_to_geotiff()` — a prototype-stage confidence flag, not a capability check |

**Derived boolean properties** — branch on these before calling
access-method-specific code, since not every dataset supports every path:

- `has_zarr` — at least one Zarr URL present
- `has_wmts` — both `wmts_url` and `wmts_layer_name` present
- `has_cds_retrieve` — `cds_retrieve_url` present
- `extraction_supported` — `has_zarr or has_cds_retrieve` (i.e. can produce a GeoTIFF via *some* path)

**Export helpers**: `.to_qgis()` (returns `QgsRasterLayer` kwargs when
`has_wmts`, else `None`), `.to_dict()` (JSON-serialisable), `__repr__`
(compact summary like `LayerDescriptor(id='...', service='C3S', access=['zarr', 'wmts'])`).

## 4. How a descriptor gets built

Two builder functions, chosen by which snapshot(s) contain the dataset:

- **`_descriptor_from_arco(dataset_id, arco_entry, cds_entry, aliases)`** —
  used when the dataset is in the ARCO snapshot. Picks a "primary subset"
  (`_pick_primary_subset`: prefers `sfc` → `all` → `surface` → first
  alphabetically), pulls bbox/time/variables/Zarr URLs/WMTS from it, and
  layers in CDS metadata (keywords, retrieve links) if a matching CDS entry
  exists. Also derives a per-variable **colormap hint** (`_colormap_for_variable`
  — a small hardcoded table: `t2m`→RdBu_r, `tp`→YlGnBu, `pm2p5`→YlOrRd, etc.,
  falling back to `viridis`).
- **`_descriptor_from_cds_only(dataset_id, cds_entry)`** — used for datasets
  present only in the CDS STAC snapshot (no ARCO access at all). Produces a
  "metadata-only" descriptor — no `zarr`/`wmts` fields, only CDS retrieve
  links if present.

### Multi-subset variable resolution

ARCO datasets often split their variables across multiple subsets (e.g.
`reanalysis_era5_land` has eight, like `sfc-soil-temperature`,
`sfc-pressure-precipitation`). The WMTS layer identifier encodes the subset,
so `_arco_subset_for_variable(dataset_id, variable)` resolves the *correct*
subset for a specific variable — rather than assuming every variable lives
in the dataset's "primary" subset. It also special-cases the pre-composed
wind vector layer (`wind`, `wind10`, `wind100`, ...), which isn't listed in
any subset's `variables` map directly but is resolved via its underlying
`u`/`v` components. This function is reused by [`wmts.py`](../geobridge/modules/wmts.py)
when building a `WmtsLayer`.

## 5. Public API

### `discover(...)`

```python
gb.discover(
    keyword: str | None = None,          # substring match on id/title/abstract/keywords
    services: list[str] | None = None,   # subset of {"C3S", "CAMS", "CEMS"}
    variable: str | None = None,         # substring match on variable list
    bbox: tuple | None = None,           # (west, south, east, north) — spatial intersection
    time_after: datetime | None = None,  # keep datasets whose data extends past this date
    extraction_only: bool = False,       # keep only has_zarr or has_cds_retrieve
    arco_only: bool = False,             # keep only has_zarr (fast, synchronous path)
    cds_download_only: bool = False,     # keep only cds_download_supported=True
) -> list[LayerDescriptor]   # sorted alphabetically by id
```

Filters are ANDed together. Passing an unknown value in `services` raises
`ValueError` immediately (fails fast rather than silently returning nothing).

### `discover_one(dataset_id, **kwargs)`

- **No kwargs** → fast direct dict lookup by id (tries ARCO underscore form
  first, then CDS hyphen form). Returns `None` if not found in either
  snapshot.
- **With kwargs** → routes through `discover(**kwargs)` and returns the
  first result whose id contains `dataset_id` (case-insensitive substring,
  not exact match) — useful for combining an id hint with other filters.

## 6. Typical usage

```python
import geobridge as gb

# Browse — no authentication needed
for ds in gb.discover(keyword="temperature", arco_only=True):
    print(ds.id, ds.variables[:5])

# All datasets extractable via either path (as of the bundled snapshot: 136)
for ds in gb.discover(extraction_only=True):
    print(ds.id, "ARCO" if ds.has_zarr else "CDS API")

# Look up a single dataset
ds = gb.discover_one("reanalysis-era5-single-levels")
print(ds.zarr_time_chunked, ds.has_wmts)
```

## 7. Relationship to the other access-path modules

`discover.py` is the **catalogue layer** — it doesn't move any data itself.
It's the thing you consult first to find out *whether* and *how* a dataset
can be accessed, then hand off to:

- `gb.zarr_to_geotiff()` ([EXTRACT.md](EXTRACT.md)) when `has_zarr`
- `gb.cds_to_geotiff()` when `has_cds_retrieve` (no ARCO Zarr available)
- `gb.wmts_layer()` ([WMTS.md](WMTS.md)) when `has_wmts`, for map preview tiles

Note `geobridge/modules/extract.py` does **not** import from `discover.py`
— it has its own independent snapshot-loading logic (`_get_dataset_entry`)
because it needs a richer, subset-resolved shape (dimensions, native
resolution, longitude convention) than `LayerDescriptor` exposes. Keep this
in mind if the two ever appear to disagree about whether a dataset/variable
combination is available — they read the same YAML but process it
differently.

Two more modules build on the same snapshots but for different purposes:

- [FORM.md](FORM.md) — `gb.fetch_form()`/`validate_request()` fetch the
  live CDS download-form schema and constraints to validate a
  `cds_to_geotiff()` request before submitting it.
- [SEMANTIC.md](SEMANTIC.md) — `gb.semantic_search()`/`semantic_resources()`
  resolve a free-text query (e.g. "urban heat island") to a concrete
  dataset/variable, one signal reading this same ARCO snapshot directly.
